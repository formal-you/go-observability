# 需求澄清与收敛

> 状态：draft，待讨论。目标：模糊需求不靠猜，先收敛再动手。

## 触发条件

用户 prompt 缺少 目标 / 范围 / 验收 任意一项，或与既有决策（CONTEXT.md / Accepted ADR / CHANGELOG / 黑盒断言）冲突时。

## 收敛步骤

1. 一句话复述任务与验收，先对齐再深入；
2. 写契约草案（模板见 [templates/requirement-contract.md](templates/requirement-contract.md)）：问题、范围/非范围、验收、影响；
3. 列假设清单：能黑盒表达的歧义先写黑盒测试；不能的列为「需确认项」交给用户；
4. 三档改动分级决定收敛深度：
   - 小（修 bug / 一行）：直接做，只确认验收
   - 中（新功能 / 改逻辑）：契约草案 + 关键假设确认
   - 大（重构 / 核心模块）：完整收敛 + ADR 草拟 + 设计由用户拍板
5. 只问影响范围 / 验收 / 兼容性 / 安全类问题；普通实现细节不反复问用户。

## 产出

- 契约草案 → 写入 `docs/gitops/issues/NNNN-<slug>.md`；
- 需确认项 → 显式提交用户，得到答复后再进契约先行阶段。
